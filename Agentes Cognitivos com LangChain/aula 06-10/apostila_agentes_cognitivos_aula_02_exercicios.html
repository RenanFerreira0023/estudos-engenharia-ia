Tema da aula

Construir cadeias reutilizáveis com prompts, modelos de chat e saídas estruturadas, utilizando a interface Runnable e duas formas de composição.

Sobre os materiais: a transcrição é da aula 2. O PowerPoint anexado corresponde à aula 1, de 05/10, e anuncia estes assuntos nos próximos passos. Este material segue a transcrição da aula 2, sem misturar os conteúdos das duas aulas.

O que o professor ensinou

1. O que é uma chain

Trecho: 00:03–00:09.

Uma chain é uma cadeia de processamento: uma etapa produz o que a próxima etapa precisa para continuar. Nesta aula, o fluxo principal foi preencher um template, enviar o prompt ao modelo e receber a resposta.

Ideia essencial: a aula construiu chains. Ao final, o professor esclareceu que ainda faltavam componentes para chegar aos agentes que seriam construídos nas próximas aulas.

2. Ambiente de trabalho e consumo por API

Trecho: 00:09–00:21.

O professor utilizou Google Colab para mostrar o código em blocos. As bibliotecas específicas do LangChain precisavam ser instaladas. Para projetos posteriores, anunciou organização em arquivos Python separados.

O modelo foi acessado pela API da OpenAI, com a chave disponível no ambiente da aplicação. Para os exemplos dessa aula, o processamento do modelo acontecia no provedor e não exigia GPU no Colab.

As falas sobre preços e alternativas de acesso foram comentários feitos na aula, não uma comparação atual de serviços.

3. Modelos de chat e suas respostas

Trecho: 00:17–00:29.

A classe utilizada foi ChatOpenAI. O professor mostrou que a resposta é uma mensagem estruturada, normalmente um AIMessage, com conteúdo e informações adicionais sobre a execução.

O atributo content contém o texto da resposta. Também foram mostrados metadados, como modelo e consumo de tokens.

ConfiguraçãoO que preciso entender
ModeloDefine qual modelo será utilizado na chamada.
TemperaturaAjusta a variação da geração. No teste do professor, aumentar a temperatura não mudou a resposta à pergunta simples.
TokensUnidades usadas no processamento e no consumo. Podem corresponder a palavras ou partes de palavras.

Não é necessário decorar os modelos utilizados na demonstração. O ponto principal é entender a configuração e o formato de entrada e saída.

4. Papéis e tipos de mensagem

Trecho: 00:29–00:43.

Os papéis ajudam o sistema a distinguir instruções, perguntas e respostas no contexto da conversa.

PapelClasse citadaUso
SistemaSystemMessageDefine o papel do assistente e suas diretrizes.
UsuárioHumanMessageContém o pedido ou a informação enviada pelo usuário.
AssistenteAIMessageRepresenta a resposta produzida pelo modelo.
Papel arbitrárioChatMessageMensagem genérica com papel especificado.

O professor perguntou a capital da Bahia e definiu uma instrução de sistema para terminar a resposta com três exclamações e “BBMP”. A demonstração mostrou a diferença entre o que o usuário pede e como o sistema orienta a resposta.

Também introduziu prompt injection: uma entrada que tenta fazer o modelo tratar instruções do usuário como diretrizes do sistema. Separar os papéis ajuda a organizar essas responsabilidades; a aula não apresentou uma implementação completa de proteção.

5. PromptTemplate: texto com variáveis

Trecho: 00:43–00:52.

Um template é um molde reutilizável. Os espaços entre chaves, como {contexto} e {pergunta}, recebem valores a cada uso.

O professor comparou o preenchimento à ideia de uma f-string em Python. Primeiro criou o template; depois chamou invoke com os valores para produzir o prompt; por fim, enviou esse prompt ao modelo.

A instrução da demonstração era responder somente com base no contexto e usar “Irineu, você não sabe e nem eu” quando faltasse informação. Ao fornecer um contexto sem relação com a pergunta, o modelo retornou essa frase.

O que lembrar: criar o template, preenchê-lo e chamar o modelo são etapas diferentes.

6. ChatPromptTemplate: template com papéis

Trecho: 00:52–00:55.

O ChatPromptTemplate aplica a mesma ideia de variáveis a mensagens separadas por papel. O professor colocou as diretrizes em uma mensagem de sistema e os dados em mensagens humanas.

Código de estudo: os exemplos deste HTML reconstituem os padrões descritos na transcrição. O arquivo não contém o notebook nem o código exibido na tela; portanto, não são cópias literais das células e não foram executados contra a API.

Python · padrão da aula
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "Responda com base no contexto. "
               "Se não souber, diga: Irineu, você não sabe e nem eu."),
    ("human", "Contexto: {contexto}"),
    ("human", "Pergunta: {pergunta}"),
])

prompt_preenchido = prompt.invoke({
    "contexto": "A capital da Bahia é Salvador.",
    "pergunta": "Qual é a capital da Bahia?",
})

O resultado é um prompt com mensagens preenchidas. Essa operação, sozinha, não consulta uma LLM.

7. Saídas estruturadas com Pydantic

Trecho: 00:55–01:03.

O professor criou uma classe com BaseModel e descreveu os campos utilizando Field. A estrutura continha resposta e justificativa, ambas como texto.

Depois utilizou with_structured_output para orientar o retorno do modelo conforme essa estrutura. A pergunta comparava um quilo de tijolos e um quilo de penas.

Python · padrão da aula
from pydantic import BaseModel, Field

class RespostaComJustificativa(BaseModel):
    resposta: str = Field(description="Resposta à pergunta do usuário")
    justificativa: str = Field(description="Justificativa para a resposta")

# modelo é o ChatOpenAI já configurado na aplicação.
modelo_estruturado = modelo.with_structured_output(
    RespostaComJustificativa
)
resultado = modelo_estruturado.invoke(
    "O que pesa mais: um quilo de tijolos ou um quilo de penas?"
)

Na demonstração, houve um erro associado ao modelo inicialmente configurado; o professor ajustou o modelo e conseguiu obter a saída estruturada.

Ideia essencial: estruturar a saída facilita usar a resposta nas próximas etapas do código. A estrutura organiza os campos, mas não garante que o conteúdo esteja correto.

8. Documentação e output parsers

Trecho: 01:00–01:07.

Descrições claras de campos e funções ajudam a manutenção e também podem orientar o comportamento do modelo quando essas descrições são fornecidas a ele.

O professor mostrou o CommaSeparatedListOutputParser, que transforma texto separado por vírgulas em uma lista. Essa transformação pode acontecer sem chamar uma LLM.

Python · padrão da aula
from langchain_core.output_parsers import (
    CommaSeparatedListOutputParser,
)

parser = CommaSeparatedListOutputParser()
lista = parser.invoke("OpenAI, Google, Meta")

Como aplicação, relatou um sistema que extraía termos para alimentar consultas DAX no Power BI. A saída precisava ter a estrutura adequada para alimentar a próxima etapa. A construção dessa integração não foi demonstrada.

9. Runnable: uma interface comum

Trecho: 01:07–01:22.

O professor inspecionou a classe Runnable para explicar por que diferentes componentes compartilham métodos de execução.

MétodoEntrada e retornoQuando usar, segundo a aula
invokeUma entrada, um resultado completo.Processamento em segundo plano e extração de dados.
batchVárias entradas, uma lista de resultados.Resumos, classificações e avaliações em lote.
streamUma entrada, partes de saída ao longo da execução.Chats em que o usuário acompanha a geração.

No fluxo síncrono mostrado, invoke espera o resultado completo. batch processa entradas em lote e retorna quando o conjunto termina. stream permite exibir partes da resposta conforme chegam.

O que lembrar: stream melhora o tempo até começar a mostrar conteúdo. Isso não significa que a resposta inteira termine mais rapidamente.

Python · padrão da aula
resposta = modelo.invoke("Olá, tudo bem?")
print(resposta.content)

respostas = modelo.batch(["Olá", "Tchau"])

for parte in modelo.stream("Explique o que é uma LLM em poucas palavras."):
    print(parte.content, end="", flush=True)

O professor também mencionou limites de requisições do provedor ao discutir lotes grandes. A aula não implementou controle desses limites.

10. Composição imperativa com @chain

Trecho: 01:22–01:27.

Na composição imperativa, uma função define explicitamente a sequência: preencher o prompt e chamar o modelo.

O decorador @chain transforma essa função em um componente utilizável pela interface Runnable.

Python · padrão da aula
from langchain_core.runnables import chain

@chain
def chatbot_imperativo(valores):
    prompt_preenchido = prompt.invoke(valores)
    return modelo.invoke(prompt_preenchido)

resposta = chatbot_imperativo.invoke({
    "contexto": "A capital da Bahia é Salvador.",
    "pergunta": "Qual é a capital da Bahia?",
})

A sequência fica escrita no corpo da função. Isso permite organizar processamento específico em um componente reutilizável.

11. Composição declarativa com LCEL

Trecho: 01:27–01:33.

LCEL significa LangChain Expression Language. O operador pipe, |, conecta os componentes: a saída do primeiro alimenta o segundo.

Python · padrão da aula
chatbot_declarativo = prompt | modelo

resposta = chatbot_declarativo.invoke({
    "contexto": "A capital da Bahia é Salvador.",
    "pergunta": "Qual é a capital da Bahia?",
})

O professor usa o pipe do terminal Unix como analogia para a passagem de resultados entre etapas. No LangChain, o operador representa composição dos componentes.

FormaComo a sequência aparece
ImperativaChamadas escritas passo a passo em uma função decorada.
DeclarativaComponentes conectados com o operador pipe.

As duas formas foram apresentadas. O professor prefere a declarativa e destaca a importância de manter um padrão compreensível no projeto e no time.

12. Memória, avaliação e próximas aulas

Trecho: 01:33–01:40.

Memória e fluxo conversacional serão tratados depois. O histórico precisa ser armazenado e incorporado pela aplicação; os exemplos simples desta aula não implementaram essa gestão.

LangSmith foi citado em resposta a uma pergunta sobre testes e avaliação de chains. O professor reforçou a importância de registros e análise de comportamento, mas não demonstrou seu uso.

ReAct, chains sequenciais e paralelas, roteamento e ferramentas foram anunciados para as próximas aulas.

O que preciso lembrar

  • Uma chain conecta etapas de processamento.
  • O template é o molde; o prompt preenchido contém os valores daquele uso.
  • ChatPromptTemplate organiza mensagens por papel.
  • AIMessage contém a resposta; content fornece seu texto.
  • Saída estruturada define campos para consumo pelo código.
  • invoke, batch e stream atendem formas diferentes de execução.
  • @chain organiza uma função como componente; LCEL conecta componentes com pipe.
  • As chains desta aula ainda não constituem, por si só, o agente completo.

Exercícios

Dois casos fictícios, mas próximos do trabalho real. Use somente os recursos apresentados nesta aula. O objetivo é escrever uma pequena solução em Python, sem interface gráfica, banco de dados ou integração com WhatsApp.

Desafio 1 — Assistente de dúvidas de uma oficina

Cenário: uma oficina recebe sempre as mesmas perguntas sobre funcionamento e serviços. Você precisa criar um assistente que responda com base em um texto fornecido pela oficina, sem inventar informações.

Problema pontual: receber uma pergunta e devolver uma resposta curta baseada nas regras abaixo.

Dados fictícios da oficina
contexto = """
A oficina abre de segunda a sexta, das 08:00 às 18:00.
Faz troca de óleo e alinhamento.
O alinhamento custa R$ 120.
Não realiza serviços de pintura.
"""

perguntas = [
    "Quanto custa o alinhamento?",
    "Vocês fazem pintura?",
    "Quanto custa a troca de óleo?",
]
O que usarPara quê
ChatOpenAIConfigurar o modelo de chat, como na aula.
ChatPromptTemplate.from_messagesCriar mensagens de sistema e usuário com variáveis.
LCEL: prompt | modeloConectar o template ao modelo.
invoke e .contentEnviar uma pergunta e mostrar o texto retornado.

Construa nesta ordem:

  1. Importe ChatOpenAI de langchain_openai e ChatPromptTemplate de langchain_core.prompts. Configure o modelo. Considere a chave da API já disponível no ambiente.
  2. Crie uma mensagem system orientando o assistente a responder em português, brevemente, somente com o contexto. Quando a informação faltar, deve dizer que ela não consta nas informações da oficina.
  3. Crie uma mensagem human com os espaços {contexto} e {pergunta}.
  4. Monte a chain com prompt | modelo.
  5. Para cada pergunta da lista, chame invoke com um dicionário contendo contexto e pergunta. Imprima o conteúdo de cada resposta.

Como conferir: as duas primeiras perguntas encontram informação no texto. A terceira não tem preço disponível. O assistente deve reconhecer essa falta, sem criar um valor. A redação exata pode variar.

O que entregar: um único bloco de código Python e duas frases explicando a função da mensagem de sistema e das variáveis do template. Pode escrever sem executar a API.

Desafio 2 — Organizar solicitações de suporte em lote

Cenário: uma equipe de suporte recebe mensagens livres de clientes. Antes de distribuir o trabalho, precisa transformar cada mensagem em uma ficha com campos definidos.

Problema pontual: processar três mensagens e obter uma ficha estruturada para cada uma, em vez de receber um parágrafo difícil de usar no código.

Mensagens fictícias dos clientes
mensagens = [
    "Sou Ana. Não consigo entrar no sistema desde hoje cedo.",
    "Meu nome é Bruno. Gostaria de saber como alterar meu e-mail.",
    "O relatório de vendas aparece em branco quando abro a página.",
]
O que usarPara quê
BaseModel e Field, de PydanticDefinir os campos e explicar como preenchê-los.
ChatPromptTemplateOrientar a extração e receber {mensagem}.
with_structured_outputSolicitar o retorno conforme a classe definida.
LCEL e batchMontar o fluxo e processar a lista de entradas.

Sua ficha deve ter exatamente estes campos:

  • cliente: str — nome informado na mensagem; quando ausente, usar “Não informado”.
  • resumo: str — descrição curta da solicitação, sem adicionar fatos.
  • categoria: str — usar “erro” quando houver uma falha relatada, ou “dúvida” quando o cliente pedir orientação.

Construa nesta ordem:

  1. Crie a classe FichaSuporte, herdando de BaseModel, com os três campos acima. Use Field(description=...) para descrever cada campo e suas regras.
  2. Crie um template com mensagem de sistema para extrair apenas o que aparece na mensagem. A mensagem humana deve conter a variável {mensagem}.
  3. Use um modelo de chat configurado que suporte saída estruturada, como no exemplo da aula. Crie modelo_estruturado = modelo.with_structured_output(FichaSuporte).
  4. Monte chain = prompt | modelo_estruturado.
  5. Transforme a lista de textos em uma lista de dicionários, cada um com a chave mensagem. Passe essa lista para chain.batch(...).
  6. Percorra os resultados e imprima os atributos cliente, resumo e categoria de cada ficha.

Como conferir: devem existir três fichas, uma por mensagem. A última precisa indicar nome ausente. Os resumos devem preservar o pedido original. Verifique se as categorias seguem as regras fornecidas.

O que entregar: um único bloco de código Python e uma frase explicando por que usar saída estruturada ajuda a próxima etapa do sistema. Pode escrever sem executar a API. Não precisa resolver os problemas dos clientes, atribuir prioridade ou criar um sistema de chamados.
